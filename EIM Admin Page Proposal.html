Proposal · EIM AI Chatbot

An admin page that shows how the chatbot is doing — and lets us make it better

Today, administrators can only see one number. This proposal adds a single page that answers three questions at a glance: Is the chatbot being used? Is it answering well? Where does it need help from a person?

Admin-only access Live figures from the chatbot's own records Policy owners can correct answers All examples below use illustrative data
01 · Why it matters

Three questions stakeholders keep asking

The chatbot already records every conversation, every thumbs-up or thumbs-down, and every time a question is passed to a practice owner. The admin page simply puts that information in front of the people who need it.

📈

Is it being used?

How many conversations happen, by how many people, and when. This tells us whether the roll-out is landing and when to expect peak demand.

✅

Is it answering well?

What users say about the answers (thumbs up / down) and what policy owners say after reviewing them (correct, incomplete, has errors, unclear).

🙋

Where does it need a person?

How often questions are escalated to a practice owner — automatically, when the chatbot is not confident, or manually, when a user asks for help.

Today

A single number

The current admin page confirms that an administrator is signed in and shows the total count of conversations. Nothing else.

Admin Total sessions: 1,284
Proposed

A dashboard and a review console

Same sign-in, same page — now with:

  • Usage, quality and escalation figures for any date range
  • Daily trends so changes are visible, not just totals
  • A list of conversations that need a reviewer's attention
  • A simple form for policy owners to correct an answer — which the chatbot then uses going forward

04 · Correcting an answer

How a policy owner improves the chatbot

The most valuable part of the admin page is not the charts — it is the loop that turns a reviewer's expertise into better answers. It takes four steps and no technical knowledge.

Open a conversation

From the review console, pick a conversation and the answer that needs a look.

Record a verdict

Choose one of four: Correct, Incomplete, Has errors or Unclear.

Write the right answer

If the answer was not fully correct, type what the chatbot should have said, in plain language.

The chatbot learns

The corrected answer is added to the chatbot's knowledge, so the next person who asks the same thing gets the approved answer.

The correction form

Everything the reviewer sees. Try it.

What is the filing deadline for an EIM issue once it has been discovered?
Issues should be filed promptly after discovery, in line with the Enterprise Issue Management Policy.
Issues must be filed within 30 calendar days of discovery, as set out in the Enterprise Issue Management Policy, section "Issue Identification and Filing".
Saved as version 1. The chatbot will use this answer from now on.

What if two reviewers disagree?

Corrections are kept as numbered versions. If a second reviewer submits a different correction for the same answer, the page flags it as an unresolved conflict and nothing changes until someone with authority picks the version to accept. The accepted version is the one the chatbot uses.

Why this matters: it means the chatbot never silently "learns" something contested. Every change to its answers has a named reviewer, a date, and an approval.

Who can do this?

Only users marked as administrators can open the admin page. Everyone else is sent back to the normal chat. The same rule is enforced behind the scenes, so it cannot be bypassed by typing the address directly.

05 · Definitions

What each figure means

Plain-language definitions, so everyone reads the same number the same way.

ConversationsThe number of chats started in the selected period. One person asking several questions in one sitting counts as one conversation.
Unique usersHow many different people used the chatbot in the period.
Messages per conversationAverage number of questions a person asks in one conversation. Higher often means people are digging into a topic; very low can mean they gave up.
Escalation rateThe share of questions that were passed to a practice owner, either automatically (the chatbot was not confident) or manually (the user asked for a person).
User satisfactionOf the answers users rated, the percentage that received a thumbs-up.
Peak hourThe hour of the day (Eastern Time) with the most questions. Helps plan when practice owners should be available.
Policy owner feedbackVerdicts recorded by reviewers: Correct, Incomplete, Has errors, Unclear. Based on expert review, not user opinion.
Answer timeAverage seconds from a user pressing send to the full answer appearing. Shown alongside its two parts: finding the relevant policy text, and writing the answer.
All figures on this page are illustrative. In production, every number is calculated from the chatbot's own records for the selected date range.
